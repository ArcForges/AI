# Reuse and provenance (WP00.03)

The current AI repository implements the [Design provenance profile](https://github.com/ArcForges/ArcForges-Design/blob/5322d698a1b650a52a5a139d986dd85b00b48581/docs/assurance/reference-coverage-and-provenance.md). Its inventory includes tracked files, tracked ignored files and non-ignored new files. The retired initialization repository is not an input.

Before copying, translating, porting or structurally reusing source, tests, assets or generated material, complete `eng/provenance/template.json` and obtain a material-specific review. Store the approved record as `eng/provenance/records/<name>-r<N>.json`. Register exact target hashes in `eng/provenance/files.json`, or register the owning artifact and immutable profile for material introduced during packaging. All ten evidence subjects, generator/input identities and any temporary removal owner/trigger are mandatory. A template is never an approved record.

Source-text evidence hashes use UTF-8 with LF line endings; archive hashes cover raw bytes. Target bindings explicitly declare their normalization. Keep the original upstream bytes and package/archive integrity evidence with the review so that line-ending normalization remains independently reproducible.

The Licensing and Provenance Owner approves compatible dispositions within the five-row policy in `eng/policy/reuse-policy.json`; maintainer-authorized implementation reviews retain the reviewer, date, source evidence and rationale. Boundary questions go to the Architecture Owner and product decisions to the Product Owner. An incompatible or unresolved contribution must be recorded in `eng/provenance/conflicts/<id>.json` with its material, evidence, boundary, owner, required decision, blocking status and resolution. It cannot be accepted or distributed until resolved. There is no silent licence exception, CLA, proprietary grant or omitted target.

Used records are immutable. Changed material or intent requires a new reviewed record with `supersedes`; removing a target retires its binding and preserves history. CI compares with the trusted event base using complete Git history. Missing history fails closed. Local branches compare with fetched `origin/main`; the primary branch compares with its committed baseline. The source checker rejects unclassified files, changed reuse, unsafe paths, ambiguous JSON, missing evidence, incomplete reviews, abandoned records, unresolved conflicts and changed notices. Complete contribution review remains necessary: an inventory cannot establish that newly inserted code is original.

`eng/provenance/NOTICE.txt` is generated deterministically from active records. To regenerate after admitting a reviewed record, update the inventory, then invoke `auditProvenance` with `{ writeNotice: true }` from `eng/provenance.mjs`. Preserve all complete licence and NOTICE documents. A legal-document record grants only its reviewed reproduction scope; it does not admit the implementation governed by that document.

## Candidate and continuing verification

`npm run check` includes source audit and failure tests. `pretest:tooling` builds the actual locked Wrangler candidate for positive and adversarial artifact tests. `npm run types` and the CI diff check reproduce the tracked declaration. Run `npm run build`, `npm run verify:candidate` and `npm run test:bundle` for the actual artifact. The compiled Workflow test explicitly mocks inference; real model execution remains the separate main deployment gate.

The candidate includes `provenance.json`, the full active records, source identity, source NOTICE and complete applicable legal texts. The verifier checks the Worker against its independently reviewed hash, the closed parsed/emitted graph, source-map bodies and mappings, generated README template, locked package graph, exact deployment-configuration transformation and runtime SBOM. Recomputing the outer manifest cannot authorize changed code, missing notices, new resources or altered source records. SBOM root identity uses `@arcforges/ai`, independent of checkout directory names. Both protobuf runtime versions and their dependency edges must remain represented.

Deployment verifies the same candidate again and promotes it without rebuilding. Source, local runtime, real Cloudflare inference and public release-byte evidence remain separate. A newly observed dependency, upstream revision, generated resource, legal-text change or configuration requires a newly reviewed profile and superseding record before promotion. Models hosted by Workers AI and development-tool implementations are not bundled by this Worker.
